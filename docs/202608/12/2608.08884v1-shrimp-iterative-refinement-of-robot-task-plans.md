## 摘要
随着协作机器人进入制造、农业和医疗保健等领域，编程或调整机器人行为通常需要大多数终端用户所缺乏的机器人专业知识。自然语言降低了这一门槛。大型语言模型（LLM）的最新进展使得将自然语言转化为机器人任务计划成为可能。然而，基于语言的任务规范存在语义歧义，且生成模型缺乏语言指令如何转化为机器人动作的透明度，使用户难以在执行前验证计划。为解决这些问题，我们引入了SHRIMP，一个允许用户使用自然语言自动生成分层机器人基本计划，并通过重新提示和显式纠正迭代修订其计划的系统。在每次修订中，SHRIMP允许用户在仿真中验证其计划，一旦满意，即可在物理机器人上执行。通过一项涉及参与者规划桌面厨房任务（n=35）的用户研究，我们验证了SHRIMP提高了感知控制并增强了机器人透明度。系统视频和源代码可在https://wisc-hci.github.io/SHRIMP获取。

## Abstract
As collaborative robots have entered domains such as manufacturing, agriculture, and healthcare, programming or adapting robot behavior typically requires robotic expertise that most end users lack. Natural language lowers this barrier. Recent advancements in large language models (LLMs) have made it feasible to translate natural language into robot task plans. However, language-based task specification suffers from semantic ambiguity, and generative models lack transparency for how language instructions become robot actions, making it difficult for users to validate the plan before execution. To address these issues, we introduce SHRIMP, a system that allows users to automatically generate a hierarchical robot primitive plan using natural language and iteratively revise their plan through re-prompting and explicit correction. At each revision, SHRIMP allows users to validate their plan in simulation, and once satisfied, execute it on the physical robot. Through a user study involving participants planning tabletop kitchen tasks (n=35), we validate that SHRIMP improves perceived control and enhances robot transparency. System videos and source code are available at https://wisc-hci.github.io/SHRIMP.

## 1. 论文的核心问题与整体含义

- **研究背景**：协作机器人已在制造、农业、医疗等领域得到应用，但编程或调整机器人行为通常需要机器人专业知识，终端用户（如现场操作员、非技术从业者）难以胜任。自然语言交互被视为降低这一门槛的可行途径，而大语言模型（LLM）的发展使自然语言到机器人任务计划的翻译变得可行。
- **核心问题**：
  - **语言歧义**：自然语言指令天然存在表达不精确、指代不清等问题，例如“把物体向左移”没有指定移动距离、参考坐标系或具体对象。
  - **生成模型不透明**：LLM/VLA等生成模型常被视为“黑箱”，用户难以理解语言指令如何转化为机器人动作，也无法在真实执行前有效验证计划。
- **研究目标与意义**：为了解决上述问题，论文提出了 **SHRIMP（Simulation-driven Human-in-the-loop Refinement Interface for Manipulation Planning）** 系统。该系统允许用户用自然语言生成**分层机器人原始动作计划**，在**物理仿真**中迭代修订和验证，最终在实体机器人上执行，从而在保持自然语言易用性的同时，提升用户对计划的**控制力**和**透明度**。
- **整体含义**：SHRIMP 将结构化计划分解与物理仿真结合，构建了“检查→纠正→验证”的闭环，为非专家用户提供了一种安全、可解释的机器人任务规划工作流，代表了语言驱动机器人编程中“人机协同迭代”方向的重要探索。

## 2. 论文提出的方法论

### 2.1 核心思想
- 以**层级原始动作（hierarchical primitive plan）** 作为计划表示和交互的基本单位。
- 通过**LLM自动生成计划**（使用GPT 5.1），结合**物理引擎（Isaac Sim）仿真**进行验证。
- 用户可以通过**自然语言重新提示（re-prompting）** 或**显式编辑（explicit correction）**（如修改参数、重排动作顺序）来迭代修订计划，在仿真中预览每一步效果，满意后再执行到真实机器人。

### 2.2 系统工作流（见图1、图2）
1. 用户通过界面将物理场景中的物体与仿真场景进行对应（物体定位跟踪）。
2. 用户输入自然语言任务提示（如“清理桌子，把所有东西放进盒子”）。
3. 后端LLM根据机器人配置、可用原始动作列表、场景物体位置和用户提示，生成分层计划。
4. 计划包含**高层原语**（如 pick、pour、pick_and_place）和**低层原语**（如 move_to_pose、grasp、release、tilt_in_hand、wait），每个原语带有参数。
5. 用户可以在仿真环境中**执行整个计划**或**逐步执行**每个原语，观察机器人动作与物体交互的物理效果。
6. 用户通过重新提示、调整原语顺序/参数进行迭代；参数编辑时，仿真中会显示红箭头指示位姿。
7. 每次修改后的计划保存在“Task History”中，可回退到旧版本。
8. 用户满意后，在物理机器人上执行计划。

### 2.3 计划生成与验证细节
- **原语设计**：低层原语是机器人动作的基本单元，高层原语由低层原语序列组合，每个原语带有参数（如表1所示）。
- **LLM生成**：使用GPT 5.1，输入包括机器人配置、原语列表、物体位置和用户任务文本；提示词优先选择高层原语。
- **三次验证检查**：
  1. **抓取检查**：验证grasp原语是否在规划的执行位置能正确抓取目标物体；若机械臂末端位姿距物体过远，则用物体跟踪得到的位姿替换。
  2. **臂间碰撞检查**：若双臂末端执行器距离过近，则插入缩回（retract）动作以避免碰撞。
  3. **机器人与物体碰撞检查**：若运动过程中手臂或抓持物体与其他物体碰撞，则提升轨迹高度以避免碰撞。

### 2.4 系统架构
- 硬件：两个7自由度Franka Emika Panda机械臂，各配12自由度Tesollo 3指夹爪；RGB-D RealSense d435相机；使用YOLO11进行物体定位。
- 软件：仿真引擎为Isaac Sim，运动控制层相同（数字孪生）；逆运动学用RangedIK；使用PD扭矩控制器+科里奥利补偿；后端为FastAPI REST API，前端为纯JS/HTML+Tailwind，仿真画面通过WebRTC传输；系统跨两台计算机（一台实时内核控制机器人，一台NVIDIA GPU运行仿真和UI），之间用ROS2通信。

## 6. 论文的主要结论与发现

- **H1（控制力）成立，H2（透明度）成立**：Plan+Edit条件相比No-Plan基线，在感知自主性（p=0.007）和透明度（TOROS，p=0.026）上均有显著提升。
- **Plan-Only与No-Plan无显著差异**，且Plan-Only与Plan+Edit之间也无显著差异，说明**仅查看高层计划不够，需要结合“查看+交互编辑”的综合功能**才能显著提升用户的控制和透明度。
- **H3（可用性）不成立**：三个条件的SUS得分无显著差异，且整体可用性得分低于平均水平（所有条件平均分不高），可能反映非专家对系统不熟悉。
- **任务负荷增加**：Plan+Edit相比Plan-Only显著提高NASA-TLX分数（p=0.002），且此效应在简单任务（Clean the Table）中更明显，说明附加的低层细节和编辑功能在简单任务中会造成不必要认知负担。
- **用户确实在迭代**：Plan+Edit中平均修订次数（6.88）和仿真次数（7.61）显著高于No-Plan（3.68/4.65）和Plan-Only（3.80/4.31）。
- **三种提示迭代策略**：Stepwise（逐步拆分）、Cumulative（逐步累积）、Oneshot（一次性全量），用户会混合使用。
- **LLM非确定性导致挫败感**：相似的提示可能产生不同的计划，导致前后不一致，用户感到困惑，并与较低可用性相关。
- **学习效应**：任务成功与试验顺序有关（ρ=0.337, p<0.001），用户随着使用次数增多而更熟练。
