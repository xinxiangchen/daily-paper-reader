## 摘要
人类通过保留早期动作已建立的知识，同时不断调整正在进行的运动，来执行长时间跨度的操作。相比之下，动作分块的视觉-语言-动作（VLA）策略在每次查询时都会从当前输入重复规划。现有方法要么通过记忆保留长期任务证据，要么通过动作重用和集成保留短期运动，使得跨查询交接不完整。我们引入了ChainVLA，一个1.2B参数的VLA策略，通过联合且可修订的执行状态来链接连续查询。进度上下文将循环工作状态与稀疏事件记忆相结合，以携带从观测中提取的任务进度，而运动尾部则将先前预测的未执行延续部分输入到状态构建和动作生成中。这两个组件共同调节一个解码器，该解码器在最新观测下重新生成每个动作周期，使携带的状态能够指导下一次预测而不固定它。ChainVLA在RMBench上达到62.8%的平均成功率，在四个LIBERO套件上达到98.8%，而移除运动尾部或进度上下文分别将RMBench成功率降低至11.2%和3.0%。这些不对称的消融结果与运动连续性有助于保留推断任务进度所依赖的观测流这一观点一致。

## Abstract
Humans perform long-horizon manipulation by retaining knowledge of what earlier actions have established while continuously adapting the motion underway. By contrast, action-chunked vision-language-action (VLA) policies repeatedly replan from the current input at each query. Existing methods preserve either long-term task evidence through memory or short-term motion through action reuse and ensembling, leaving the cross-query handoff incomplete. We introduce ChainVLA, a 1.2B-parameter VLA policy that chains successive queries through a joint and revisable execution state. Progress Context combines a recurrent Working State with sparse event memory to carry observation-derived task progress, while Motion Tail feeds the preceding prediction's unexecuted continuation into state construction and action generation. Together, the two components condition a decoder that regenerates each action horizon under the latest observation, allowing the carried state to guide the next prediction without fixing it. ChainVLA reaches 62.8% average success on RMBench and 98.8% across four LIBERO suites, while removing Motion Tail or Progress Context reduces RMBench success to 11.2% and 3.0%, respectively. These asymmetric ablations are consistent with motion continuity helping preserve the observation stream from which task progress is inferred.

# ChainVLA 论文详细总结

## 1. 核心问题与研究动机

- **问题背景**：长时间跨度（long-horizon）的机器人操作需要连续的执行过程：每个决策既依赖于之前动作已达成的任务进度，也依赖于当前正进行中的运动延续。  
- **现有方法的不足**：动作分块（action-chunked）VLA 策略在每个查询时重复规划新动作序列，但对“跨查询交接”不完整——  
  - 任务层面：此前查询中获得的场景证据可能已不在当前视野中，导致决策信息不足（如 RMBench 的 Put Back Block 任务）；  
  - 运动层面：重规划会直接丢弃上一预测中未执行的部分，导致新动作与旧动作在边界处出现不一致。  
- **已有两条补充路线尚未完成统一**：  
  - 记忆增强策略：保留长期任务证据（循环状态、选帧、压缩历史），但不保留未执行的动作延续；  
  - 动作集成策略：通过时序集成、实时执行或原生延续保留短期运动，但无法保留更早的任务证据。  
- **核心问题**：如何让 VLA 策略在跨查询时同时链接“任务进度”和“运动延续”，同时仍能对新观测保持响应能力？

## 2. 方法论

### 2.1 核心思想

ChainVLA 将每次查询所需的跨查询上下文建模为统一的、可修订的“执行状态”  
`sk = (gk, uk)`，其中：

- `gk = Progress Context（进度上下文）`：由循环工作状态（Working State）与稀疏事件记忆（Sparse Event Memory）融合而成，携带观测推导出的任务进度；
- `uk = Motion Tail（运动尾部）`：前一查询预测但尚未执行的动作后缀，作为运动延续的先验。

每次查询读取该状态，更新后传递给下一次查询，从而将独立解码的动作块连接成跨查询的“链”。

### 2.2 关键公式与流程

- **历史条件化生成**：  
  `Πθ(· | xk, sk) ≈ Π*(· | Hk)`，  
  `sk+1 = Fθ(sk, xk)`  
  其中 `xk = (ok, rk, ℓ)` 为当前观测、本体感受与语言指令。

- **查询转换式（Eq. 3）**：  
  `(Ak, Wk, Ck+1) = Fθ(xk, Dk, Wk-1, Ck, uk)`  
  `uk+1 = Tail(Ak)`  
  其中 `Dk` 为已执行动作历史，`W` 为 Working State，`C` 为事件记忆，`Tail(Ak)` 为未执行后缀。

- **工作状态更新（Eq. 4）**：学习的工作查询（working queries）与当前多模态 token 做交叉注意力，并递归结合上一轮 live tokens；同时池化得到检索摘要 `¯Wk`。

- **事件检索（Eq. 5）**：基于当前执行状态估计与查询时间编码，使用“年龄段感知的余弦相似度”从稀疏事件记忆检索相关记录；事件写入由任务阶段转移或固定周期规则触发。

- **运动尾部两路注入**：  
  - 作为 token 进入 Working State 构建；  
  - 作为动作生成的轨迹初始化：`eA(0) ~ N(I(uk), σu²I)`，即用对齐后的前一个未执行后缀作为均值、加噪声初始化解码器。  
  解码器仍会在最新观测和上下文条件下重新生成全部位置，因此该先验是可修订的，而非固定计划。

- **训练**：按 episode 顺序展开查询转换；下一查询有 50% 概率使用上一查询的“分离梯度”运动尾部，否则掩码；使用条件流动作目标、阶段监督（有标注时）以及重叠一致性正则化。

## 3. 实验设计

### 3.1 数据集与基准

- **RMBench**：面向记忆依赖操作的五任务基准，任务包括观测/重排/放回/交换等；每个任务训练一个模型，评估 100 个 rollout episodes，作为主要诊断场景。  
- **LIBERO**：包含 Spatial、Object、Goal、Long 四套件；每套件微调一个模型，每个任务评估 50 个 episodes，作为广度验证。

### 3.2 对比方法

- RMBench 对比：DP、ACT、π0.5、X-VLA、MemER、MemoryVLA、Mem-0、MemoAct、PAM、Goal2Skill 等；  
- LIBERO 对比：OpenVLA、SpatialVLA、π0-FAST、GR00T-N1、π0、π0.5+KI、PAM、MemoryVLA、CronusVLA、X-VLA。  
- 另外还有系统内部消融和多种替代式控制条件（FIFO History + Temporal Ensemble、Linear Continuation、Temporal Ensembling 等）。

### 3.3 主要实验结果

- **RMBench**：ChainVLA 平均成功率 62.8%，超过有完整五任务覆盖的最强基线 Mem-0（52.8%，8B+2B）。  
- **LIBERO**：四个套件平均 98.8%，每个套件均高于 98%，其中 Long 为 98.2%。  
- **消融结果**：  
  - 移除 Motion Tail → 11.2%  
  - 移除 Progress Context → 3.0%  
  - 两者全移除 → 1.6%  
  - 仅移除事件读取：32.2%，仅移除轨迹初始化：38.0%；  
  - 用固定长度观测历史 + 时序集成替代携带状态 → 35.6%。
- **边界诊断**：与移除 Motion Tail 相比，Full 在所有四项边界指标（位置间断、朝向间断、边界二阶差分、三步重叠 RMSE）上降低约 40%–57%。
- **后处理平滑控制**：即使 Linear Continuation 和 Temporal Ensemble 让边界更平滑，成功率仍极低（0–2%），而 Full 在对应任务上为 96% 和 74%，说明平滑不等于链式状态传递。

## 6. 主要结论与发现

- 跨查询执行状态应包含两个互补部分：观测推导的任务进度和预测推导的未完成运动；  
- 两者缺一不可：去掉任意一半，RMBench 成功率降到个位数或低两位数，说明它们不是简单的独立加成，而是共同支撑策略有效性的整体状态；  
- 两个组件的消融效果不对称（去掉 Motion Tail 损伤更大），与“运动连续性通过保持观测流来支撑后续任务进度推断”的假设一致；  
- 仅靠解码后的动作平滑（时序集成、线性延续）无法替代模型侧的跨查询状态携带，必须让上一预测的未执行部分在下一查询的状态构建和生成阶段就产生影响。
